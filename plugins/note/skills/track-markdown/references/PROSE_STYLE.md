# track の日本語本文の表記

track ノートを新しく書く、または本文の表記を整える場合に使う既定の表記規則。
ユーザーや文書の指定を優先する。引用、資料の保存版、コード、ログの内容をこの規則で書き換えない。
文の意味や構成の良し悪しとは分けて扱う。

## 改行と補足

- 句点で改行し、一文ごとの行を基本にする。長い文は、節や列挙など意味のまとまりの境目でも改行する。
- 固定幅で折らず、語句、コード、リンク記法の途中を分断しない。段落は空行で区切り、通常の改行に末尾スペースや `<br>` を付けない。
- コード、差分、ログ、設定の断片はコードブロックにする。
- 本筋から外れる長い補足や用語の由来は脚注へ移す。対象や条件をその場で特定する短い補足は本文に残す。
- 脚注には `[^label]` と対応する定義を使う。リンクや脚注などの構文は [track Markdown](../SKILL.md) に従う。

## 記号と強調

- 括弧は半角の `()`、コロンは `: ` に揃える。行末や閉じ括弧の直前ではコロンの後にスペースを置かない。コードブロックとインラインコードは対象外。
- 地の文の挿入や言い換えにダッシュを使わず、括弧、句点、読点でつなぐ。範囲の en ダッシュ、英語の複合語、書誌情報は対象外。
- 日本語の並列には中黒やスラッシュを使わず、読点や接続表現を使う。固有名詞の内部の中黒は残す。
- 用語を散文中で初めて定義するときは太字にし、既出の用語、引用、通称を示すときは「」を使う。
- 用語と定義の箇条書きは `用語: 説明` とし、ラベルを太字にしない。
- 初出の定義以外の太字は、誤読を防ぐ否定や帰結などに限る。一節に一、二箇所を目安にし、段落ごとに揃えない。
- 見出しやリストの装飾に絵文字やチェックマークを足さない。タスクのチェックボックスなど意味を持つ構文は維持する。
- 見出しに罫線で種別と主題を詰め込まず、内容を特定できる一つの句にする。
- 段落末を「以下のとおりです:」のような述語とコロンで終えず、句点で閉じる。

## 文体の選択

- 人物そのものには原綴りを使う。歴史上の人物や人名を冠した概念に定着した日本語名がある場合は、その名称を使う。
- 論証中は「あなた」より読者の役割名を使う。直接の呼びかけは、導入や結びなど必要な箇所に限る。
- イ形容詞に「です」を続ける形を避ける既定の文体にする。文末だけでなく前後の流れも整え、確信度は変えない。ナ形容詞の「重要です」などは対象外。
- 命令調を必要以上に使わず、作業者の判断として書く。操作手順や必須条件の強さは変えない。
