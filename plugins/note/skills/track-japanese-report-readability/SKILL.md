# 日本語レポートの構成

結論だけを読む人にも、根拠を確かめる人にも必要な情報が届く構造にする。
段落の分量が均一、結論と傍証が同じ扱い、調べたことが全部残る、という三つの状態を点検する。

このスキルは文書の構造と総量を扱う。
文の意味や言い回しを直す場合は [日本語の文章規範](../track-japanese-tech-writing/SKILL.md) を使う。
track への保存と改訂の手順は [track-report](../track-report/SKILL.md) が担当する。
通読する解説は [track-explainer](../track-explainer/SKILL.md) の構成に従い、レポートの結論先出しを一律に当てはめない。

## 読者が決めることを定める

執筆前に、誰が何を決めるか、または何を知るために読むかを定める。
用途の宣言を前置きにする必要はない。採用判断なら条件と反証、再調査の防止なら出典と再現手順を優先する。
判断を求められている場合は、根拠の支える範囲で推奨を書く。
判断が割れるなら、何が分かれば決まるかを示す。

## 冒頭だけでも誤った判断をさせない

長いレポートは次の層を目安にする。短い文書では不要な層を省き、ユーザー指定の書式を優先する。

| 層 | 読者へ渡す内容 |
| --- | --- |
| 結論 | 現時点で何が言えるか |
| 要約 | 判断に必要な根拠、適用条件、制約 |
| 本文 | 根拠の詳細、手順、反証、選択肢の比較 |
| 付録 | 生ログ、全リスト、生データ、出典 |

要約には本文の答えを書く。「何を扱うか」「詳細は後述」という案内だけにしない。
本文の結論を変える留保は要約にも置き、限界を付録だけに追いやらない。
小標本、未測定、未検証を、一般的な効果や採用の保証に言い換えない。

本文では結論を支える根拠と条件を足す。
同じ結論を言い換えるだけの末尾のまとめは省くが、節だけを読む人が対象を特定するための再掲は残す。

## 重要度に応じて分量と形式を選ぶ

主論点には根拠と反証を示し、副論点や採らない選択肢は判断理由が伝わる分量にする。
節の長さを揃えるために説明を足したり、必要な根拠を削ったりしない。
複数の選択肢を示す場合も、採否の条件と判断理由を明らかにする。

| 形式 | 使う条件 |
| --- | --- |
| 散文 | 因果、理由、適用条件を順に説明する |
| 箇条書き | 並列の項目や手順を個別に確認する |
| 表 | 同じ属性で候補や測定値を比較する |
| 図 | 関係や流れを示すほうが理解しやすい |

- 項目間に因果や条件がある節を、箇条書きだけで済ませない。
- 深い入れ子や細かすぎる見出しは、表や節の統合で整理する。見出しは3階層、リストの入れ子は2段までを目安にする。
- 見出しはその節の問い、対象、結論を示す。名詞句でもよく、すべてを決め台詞に揃えない。
- 図表を読み上げるだけの本文は省き、読み方、条件、意味づけを残す。

## 構造を点検して削る

まず、見出しと各段落の先頭文だけを続けて読む。
何を結論とし、どの根拠で支えているかが追えるか確かめる。
見出しだけで拾える判断や条件がなく、全節が同じ調子で終わるなら構成を直す。
抽出用のスクリプトは必須にしない。

次の順で削る候補を確認する。

1. 前置きと調査の順路を削る。「まず調べた」「次に確認した」という発見順を、読者の判断に必要な順序に直す。出来事の時系列が因果の根拠になる場合は残す。
2. 要約、本文、末尾にある同じ主張の言い換えを整理する。本文が条件や反証を加えているなら残す。
3. 結論に必要な説明と、再現や監査のための詳細を分ける。生ログと全件リストは付録へ移し、本文に結果と確認先を残す。
4. 判断に関係しない展望や一般論を削る。実際の未解決事項は、確認すべき問いとして示す。問いを数合わせで作らない。

文の短さや lint の指摘件数だけで削らない。
引用、出典、必要な条件、不確実性を失うなら、その削除を戻す。
watch やプロジェクトノートの履歴を、この削除手順で消してはいけない。

## 出す前の確認

- 冒頭だけを読んでも、結論とその成立条件を取り違えないか。
- 本文の根拠は要約の主張全体を支えているか。反対の根拠や未確認事項を隠していないか。
- 見出しと段落先頭の通読で、論旨と情報の優先順位が分かるか。
- 削除や改訂によって、出典、数値、条件、因果の対応を壊していないか。

改訂では、変わった根拠が冒頭の結論、本文、付録に一貫して反映されているか確認する。
保存方法やノート固有の書式は、保存先の契約に従う。
